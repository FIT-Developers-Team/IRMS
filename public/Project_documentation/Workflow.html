User Authentication & Role-Based Access Control

Overview

The authentication system secures access using role-based permissions (Super vs Staff/Checker/Picker), supports 0ms offline startup via IndexedDB cache hydration, and maintains reactive session freshness with automatic inactivity locks.

Step-by-Step Workflow

  1. Application Launch & Local Session Check: main.js checks localStorage for irms_logged_in_user. If valid, hydrates IndexedDB and renders dashboard instantly (0ms). If not, redirects to login.
  2. Login Credentials Submission: Validates name + password against User_DB. On success, saves session and fetches master data. On failure, shows error toast.
  3. Session Auto-Lock & Expiry: checkAndRefreshIfExpired() monitors activity. Inactive sessions trigger password re-verification modal.
  4. Refresh Options Modal: Offers Regular Refresh (section sync) or Flush Cache & Full Resync (purge IndexedDB + full reload).

Pickup Request Workflow (Request_Checker)

Overview

Enables checkers and warehouse staff to create requests for item retrieval from checker lines. Each request generates a unique ticket ID (#RC-XXXXXX), auto-populates product metadata from SKUs_DB, and logs the request to Google Sheets.

Step-by-Step Workflow

  1. Initiate Request: Click + New Pickup Request. Opens openNewRequestModal().
  2. Form Entry & Auto-population: Auto-generates #RC-XXXXXX. Selecting a SKU populates Product Name, Categories, and Food/Non-Food classification. User selects Checker Line and inputs Qty.
  3. Validation & Submission: Validates skuCode, checkerLine, qty > 0. Dispatches to handleCreateRequest in Google Apps Script. Status set to Pending.

Picking Task & Putaway Execution Workflow

Overview

Aggregates unpicked requests from Request_Checker and Lost_And_Found, manages bulk picking assignments via a Swipe-to-Confirm slider, and oversees putaway completion into warehouse racks.

Phase A — Waiting List & Task Selection

  • Queries db.getPendingRequests() and db.getPendingLostAndFound().
  • Desktop: checkbox selection; Mobile: tap cards → Floating Action Bar shows Start Picking (N).

Phase B — Swipe-to-Confirm

  • Tapping Start Picking opens confirmation modal with swipe slider.
  • Dragging thumb ≥ 90% fires startPickingTasks(), generates #PT-XXXXXX, updates status to Picking.

Phase C — Putaway Execution

  • User opens openPutawayModal(), selects Zone-filtered rack via chip picker.
  • Submits via handleCreatePutaway → writes to Putaway, Stock_Activity (SA-XXXXXX), and updates SOH (existing row or append at bottom, never insertRowAfter).

Stock On Hand (SOH) & Stock Deduction Workflow

Overview

Provides real-time inventory visibility across all rack locations with KPI cards, multi-criteria search filters, and a controlled Stock Deduction assignment process.

Step-by-Step Workflow

  1. KPI Dashboard: Total SOH SKUs, Total Qty SOH, High Age Stock, Deduction Required.
  2. Initiate Deduction: Select row → Click Deduct Stock → Opens openStockDeductionModal().
  3. Deduction Entry: Select reason (Bad/Damaged/Expired, Lost/Missing, Discrepancy Correction, Sample/Testing). Enter Qty. To Location is locked to Deduction.
  4. Submission: Creates Stock_Movement record (Type = Stock deduction, Status = Assigned).

Stock Movement & Dual Verification Workflow

Overview

Executes rack-to-rack location transfers and final stock deduction authorization. Completing a movement requires a Dual Verification step confirming SKU Code and Location to prevent warehouse errors.

Step-by-Step Workflow

  1. View Active Movements: Tasks filtered into Transfer location or Stock deduction.
  2. Initiate Verification: Click Complete Task → Opens openCompleteMovementModal().
  3. Step 1 — SKU Verification: Scan or type SKU Code. Mismatch blocks completion.
  4. Step 2 — Location Verification: Confirm destination rack (or Deduction for stock deductions).
  5. Execution: Status = Done. Dual activity log: [-] from source rack + [+] to destination rack. SOH updated live.

    I --> J["Log Outbound Activity\n-Qty in Stock_Activity"]

Lost & Found Management Workflow

Overview

Enables recording uncataloged, misplaced, or found items with ticket ID #LF-XXXXXX. Found items automatically join the picking waiting list for putaway recovery into active SOH.

Step-by-Step Workflow

  1. Log Found Item: Click + New Lost & Found Entry → Opens openLostAndFoundModal().
  2. Form Entry: Auto-generate #LF-XXXXXX. Enter SKU, Product Name, Qty. Select Found At Zone via chip picker (z-index 6000 above form modal z-index 5000).
  3. Submission: Status = Pending. Saved to Lost_And_Found sheet. Auto-appears in Picking Waiting List.
