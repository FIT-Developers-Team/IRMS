Dual-Endpoint Architecture Overview

Overview

IRMS implements a decoupled Dual-Endpoint Backend Architecture defined in src/config/googleSheets.js. Rather than routing all operations through a single server bottleneck, the application splits data reads and data writes into two specialized network channels.

The Dual-Endpoint Channels

ChannelTarget Endpoint URLProtocol & FormatPrimary Function
Read Path (Data Retrieval) https://docs.google.com/spreadsheets/d/{spreadsheetId}/gviz/tq?tqx=out:csv&sheet={sheetName} HTTP GET / Direct CSV Stream Fetches raw worksheet tables directly from Google Sheets Visualization API with zero Apps Script execution delay.
Write Path (Data Mutation) https://script.google.com/macros/s/{scriptId}/exec (`webAppUrl`) HTTP POST / JSON Payload Executes transaction writes, status updates, stock calculations, administrative CRUD, and script locking in Apps Script (`gas/Code.gs`).

Data Retrieval via Google Sheets CSV Endpoint

Overview

Data reading does not execute Google Apps Script `doGet` functions. Instead, `src/data/db.js` fetches raw CSV text directly from the public Google Sheets Visualization API (`gviz/tq`). This bypassing strategy eliminates Apps Script quota usage and delivers ultra-fast data reads.

How Data is Retrieved & Processed

  • 1
    Dispatch Parallel CSV Fetches
    `db.js` constructs parallel HTTP GET requests targeting specific worksheet tabs (e.g. `SOH`, `Request_Checker`, `Picking_Task`, `SKUs_DB`) with a unique cache-buster parameter (`t=${Date.now()}`).
  • 2
    Client-Side CSV Parsing
    The raw CSV text response is parsed line-by-line in JavaScript. Row 0 provides header column names, while subsequent rows are converted into structured JavaScript object arrays.
  • 3
    IndexedDB Store Update
    Parsed objects are written into local IndexedDB object stores, making current inventory and task data available instantly to UI components.
Architectural Advantage
Direct gviz CSV streaming allows parallel downloading of all 13 spreadsheet tabs in under 300ms, completely bypassing the 6-minute Google Apps Script execution timeout limit.

Data Mutation via Apps Script API Endpoint

Overview

All data creation, status updates, putaway records, stock transfers, deductions, and admin operations are sent via HTTP POST to the Google Apps Script Web App Endpoint (`webAppUrl`).

Payload Transmission Model

Mutations transmit a JSON body containing an `action` string and data fields:

fetch(GOOGLE_SHEETS_CONFIG.webAppUrl, {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain;charset=utf-8' },
  body: JSON.stringify({
    action: 'createPutaway',
    putawayId: 'PT-481029',
    pickingId: 'PK-391042',
    skuCode: 'SKU-8812',
    rackLocation: 'A-01-02',
    qtyPut: 10,
    operator: 'John Doe'
  })
});

Google Apps Script Routing & Controller Actions

Overview

Inside `gas/Code.gs`, `doPost(e)` parses `e.postData.contents` into a JSON object and dispatches control to specialized action handlers.

Backend Route Dispatcher (Action Handlers)

Action NameHandler FunctionTarget SheetOperation Completed
createPickingTasks handleCreatePickingTasks() Picking_Task, Request_Checker, Lost_And_Found Appends picking tasks (`PK-XXXXXX`), updates parent requests status to `Picking`.
createPutaway handleCreatePutaway() Putaway, Stock_Activity, SOH, Picking_Task Logs putaway record (`PT-XXXXXX`), logs stock activity movement, increments SOH count at target rack, and marks task `Completed`.
completeStockMovement handleCompleteStockMovement() Stock_Movement, Stock_Activity, SOH Executes 2-step verification, decrements SOH at source rack, increments SOH at destination rack (transfers only), and updates movement status to `Done`.
createLostAndFound handleCreateLostAndFound() Lost_And_Found Appends stray item record (`LF-XXXXXX`) with status `Pending` for picker waiting list.
addUser / deleteUser handleAddUser() / handleDeleteUser() User_DB Creates or removes staff account credentials and role assignments.
addRack / deleteRack handleAddRack() / handleDeleteRack() Racks Adds or deletes rack location master reference records.

In-Place Stock Aggregation & Formula Safety

Overview

When stock changes occur, `Code.gs` executes in-place cell arithmetic on the `SOH` sheet rather than appending redundant rows or inserting blank lines.

Stock Aggregation Rules

  • Scans `SOH` worksheet for a row matching both `SKU Code` and `Rack Location`.
  • Row Exists: Adds putaway quantity or subtracts movement/deduction quantity from existing `qtySoh` cell in-place.
  • No Row Exists: Appends a new row at `lastDataRow + 1` without calling `insertRowAfter`.
Formula Protection
`Code.gs` explicitly skips writing to formula columns (`qtyonso`, `countso`, `qtyonldp`, `stockage`, `actionsuggestion`), ensuring Google Sheets `ARRAYFORMULA` row expansions remain completely intact.

Post-Mutation Cache Reconciliation Sync

Overview

After a client receives a successful response from Apps Script POST request, it performs a Delayed Background Reconciliation Sync:

  • 1
    Optimistic UI & Apps Script POST
    UI updates locally instantly. POST request executes on Apps Script.
  • 2
    2.5-Second Delay Buffer
    Client waits 2.5 seconds to allow Google Sheets spreadsheet engine to finish calculating formulas and flushing background saves.
  • 3
    Background CSV Re-Fetch
    Client re-downloads target sheet CSV via gviz endpoint, updating IndexedDB to mirror exact authoritative spreadsheet state.

Administrative Data Deletion Logic

Overview

Admin deletion operations locate target rows by primary key header matching and remove the row from Google Sheets using `sheet.deleteRow(rowIndex)`.

Concurrency Protection & Validation Rules

Concurrency Protection

Simultaneous POST requests acquire atomic lock protection via `LockService.getScriptLock().waitLock(10000)`, preventing race conditions during concurrent stock updates.
